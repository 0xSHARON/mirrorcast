MirrorCast Protocol Specification
Version 1.0.0 • P2P Direct Transport

This document specifies the wire format, discovery mechanisms, authorization handshake, and WebRTC signaling sequences used to establish deterministic, sub-15ms screen and audio streams between Android senders and Windows receivers.

01. Architecture

Tri-Layer Protocol Model

MirrorCast decouples discovery, control signaling, and media transport across three distinct network planes to achieve immediate connection without central relays.

LAYER 1: DISCOVERY
mDNS / DNS-SD

Broadcasts over UDP 224.0.0.251:5353 with PTR record _mirrorcast._tcp.local. Enables zero-configuration LAN discovery within 20 milliseconds.

LAYER 2: CONTROL
WebSocket Signaling

Bidirectional JSON message framing over TCP port 8080 (or USB ADB reverse tunnel). Handles device capability exchange, authorization consent, and WebRTC SDP negotiation.

LAYER 3: DATA PLANE
WebRTC SRTP

Direct PeerConnection carrying H.264 video RTP streams and Opus audio RTP packets, encrypted end-to-end with ephemeral DTLS-SRTP keys.

05. Security Model

      
Threat Model & Hardened Constraints

      

        MirrorCast is built without cloud intermediaries, preventing eavesdropping and rogue connections.
      


      

        
          

            Security Domain
            Protective Measure & Guarantee
          

        
        
          

            Media Cryptography
            DTLS 1.2 / SRTP encryption with ephemeral ECDSA/RSA keys per session. No plain RTP is ever transmitted.
          

          

            Receiver Access Control
            Incoming sessions trigger a mandatory interactive desktop prompt displaying sender hardware ID and IP address.
          

          

            PIN Verification
            Optional 4-digit numeric code with rate limiting (max 3 failed attempts per 60s) to prevent LAN brute force.
          

          

            Network Boundary
            Binds to local network interfaces only. No NAT traversal (no STUN/TURN relays) — impossible to access over the WAN.
          

          

            Telemetry & Analytics
            Zero telemetry, zero crash reporters, zero analytics SDKs, zero external DNS queries.
